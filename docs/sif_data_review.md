## 0. 이 자료의 성격 (먼저 읽을 것)

**SIF 아카이브는 사고 후에 작성된 중대재해 서술문입니다.** 이 PoC 가 다루는 작업자의 **사고 전 위험 신고**와는 다른 자료입니다.

| 구분 | 이 PoC 의 입력 (작업자 신고) | SIF 재해개요 |
|---|---|---|
| 시점 | 사고 전, 위험 상태를 보고 신고 | 사고 후, 조사 결과를 요약 |
| 작성자 | 현장 작업자 (구어체, 모호함 포함) | 조사 기관 (정제된 문어체) |
| 내용 | 현재 상태 ("배전반 앞에 박스가 쌓여 있어요") | 경위와 결과 ("…개구부로 떨어져 사망") |
| 정답의 위치 | 대부분 원문에 드러남 | 재해유발요인은 조사자가 판단한 것이며 개요에 명시되지 않을 수 있음 |

따라서 SIF 로 확인할 수 있는 것은 **"실제 현장 사고 서술문에서 위험요인을 분류하는 능력"**까지입니다. 작업자 신고 문장에서의 성능을 대신하지 않습니다.

## 6. 별도 평가 데이터 50건 구성 판단과 제안

**판단: 구성할 수 있습니다.** 다만 목적에 따라 두 가지 설계가 있습니다.

### 설계 B (권장): 현재 PoC 를 그대로 실제 서술문에 적용

현재 규칙 기반과 로컬 LLM 을 **코드와 프롬프트 수정 없이** 돌릴 수 있어, 추가 개발 없이 "실제 데이터 적용"을 보여 줍니다.

**대상:** 제조업 1,546건 중 5.1 의 **직접 대응 224건**

**선정:** 대응 코드별 층화 무작위 추출, 시드 고정

| 대응 코드 | 모집단 | 제안 추출 수 |
|---|---|---|
| FIRE_FLAMMABLE_NEAR_IGNITION | 95 | 13 |
| FALL_OPENING_UNGUARDED | 84 | 13 |
| ELEC_PANEL_OPEN | 16 | 10 |
| SLIP_FLOOR_WET / TRIP_FLOOR_DAMAGED | 19 | 10 |
| FALL_LADDER_UNSTABLE | 6 | 4 |
| 합계 | | **50** |

`PPE_NOT_WORN`(3)과 `TRIP_WALKWAY_OBSTRUCTED`(1)는 수가 너무 적어 제외합니다.

**모델 실행 전에 고정할 것** (교안 원칙과 동일):

1. 원본 XLSX 의 SHA-256
2. 대응표 (5.1 의 규칙. 라벨 문구 → 코드)
3. 추출 시드와 뽑힌 연번 50개
4. 채점 규칙과 목표치
5. (권장) **사람의 사전 판독**: 뽑힌 50건의 재해개요만 읽고 "정답 코드의 근거가 개요 문장에 드러나는가"를 예/아니오로 표시합니다. 재해유발요인은 조사자 판단이라 개요에 없을 수 있습니다. 전체 50건 점수와 "근거 있음" 부분집합 점수를 따로 냅니다.

1~4번을 git 에 커밋한 뒤에 실행합니다. 데이터 자체가 아니라 해시·연번·규칙만 커밋합니다.

**평가 기준 (제안. 목표 숫자는 실행 전에 사용자가 정함):**

| 지표 | 정의 |
|---|---|
| 정답 코드 포함률 | 대응 코드(또는 쌍 중 하나)가 예측 코드 집합에 들어 있는 비율 |
| 정확 일치율 | 예측 집합 = {대응 코드} |
| 추가 코드 수 | 정답 외에 예측한 코드 수 (과잉 분류) |
| 확인 필요 비율 | `UNKNOWN_NEEDS_CHECK` 를 낸 비율 |
| 근거 인용 검사 | 모델 근거 문구가 개요에 있는지 (기존 checks 와 동일) |
| 비교 대상 | 규칙 기반 vs 로컬 LLM, 그리고 **공단 조사자의 분류**(= 기존 방식의 결과). 시간 비교는 불가(사람 처리 시간 정보 없음) |

### 설계 A (추가 개발 필요, 이번 범위 밖): SIF 고유 분류로 평가

- `고위험작업·상황` 37종을 그대로 분류 목록으로 주고 맞히게 합니다. 모든 행에 라벨이 있고 결측이 없어 정답으로 쓰기 좋습니다.
- 이 방식은 **새 분류 프롬프트가 필요**해 현재 PoC 를 고쳐야 하므로 이번 단계에서는 제안만 합니다.
- 50건 예시: 제조업 상위 10개 작업 유형에서 5건씩 층화 추출합니다.
