## 1. 왜 바꾸려 하는가

공개 자료인 안전보건공단 「사망사고 고위험요인(SIF) 아카이브」 제조업 1,546건을 검토했습니다([sif_data_review.md](sif_data_review.md)). 그 결과는 다음과 같습니다.

- 현재 24개 코드로 직접 대응되는 사례는 224건(14.5%)이었습니다.
- 약 70% 는 작업 방법·절차에서 나온 위험이었습니다(정지 없이 정비, 적재물 무너짐, 차량 동선 등). 현재 체계에는 이런 위험이 없습니다.
- 현재 체계는 "보이는 상태" 하나를 코드 하나로 고르는 **단일 축** 구조입니다. 그래서 "무슨 작업 중에, 어떤 설비 때문에, 어떤 통제가 빠져, 어떤 사고가 날 수 있는가"를 나눠 담지 못합니다.

**조사 결과 요약**

- 국내 공식 자료에서 **숫자 코드표는 확인하지 못했습니다.** 확인한 것은 발생형태·기인물의 **명칭 체계**입니다.
- 따라서 이 설계에서 국내 분류는 "공식 명칭 + 출처 문서·버전"으로 기록하고, `code` 칸은 "미확인"으로 둡니다.
- 위험성평가 지침에는 유해·위험요인 분류표가 없습니다. KRAS 분류는 공식 원문을 확인하지 못했습니다.

## 3. 사고 전 신고와 사고 후 기록에 공통으로 쓸 정보 축

ESAW 는 사고를 **"하던 일 → 정상에서 벗어난 일(일탈) → 다친 방식(접촉)"**의 순서로 기록합니다. 단계마다 관련 물체를 따로 둡니다.

사고 전 신고는 아직 접촉(피해)이 없으므로, 같은 순서에서 **"일어날 수 있는 일"**로 바꿔 담으면 두 자료를 같은 축으로 볼 수 있습니다.

| 공통 정보 축 | 사고 전 위험 신고에서 | 사고 후 재해 기록에서 | 참조 체계 (명칭) |
|---|---|---|---|
| 작업 활동 | 신고 시점에 하던·할 작업 | 사고 당시 작업 | SIF 고위험작업·상황, 조사표 "재해관련 작업유형", ESAW Working process / Specific physical activity |
| 설비·기인물 | 위험과 관련된 설비·물체 | 재해를 일으킨 설비·물체 | 국내 기인물 명칭, ESAW Material agent |
| 유해·위험요인 | 위험 에너지·물질의 종류 | 같음 | 위험성평가 지침 정의 (분류표 없음), KRAS 요인 (미확인) |
| 통제 실패 | 빠지거나 불량한 통제 (덮개 없음, 전원 미차단 등) | 재해유발요인 | SIF 재해유발요인, 조사표 재해발생원인 4분류. ESAW 일탈은 "원인이 아니라 마지막 비정상 사건"이므로 **같은 개념이 아님** |

| 피해 여부 | 없음 / 아차사고 | 부상 / 사망 | 조사표, ESAW 범위 정의 |

## 4. 다축 구조 설계 (제안)

### 4.1 축 정의

| 축 | 값의 출처 | 비고 |
|---|---|---|
| 신고 유형 | **자체 정의** (공식 코드 없음): 위험 상태 / 불안전 행동 / 아차사고 / 재해 발생 / 정상 점검 / 판단 불가 | 기존 `NONE` 은 이 축의 "정상 점검"으로, `UNKNOWN_NEEDS_CHECK` 는 "판단 불가"로 옮겨 감 |
| 작업 활동 | SIF 고위험작업·상황 (제조 37종) 참조 + "해당 없음/불명" | 문구 사용 조건 확인 필요 (7장) |
| 설비·기인물 | 국내 기인물 대분류 명칭 (사망재해 21개) 참조 | 숫자 코드 미확인 |
| 유해·위험요인 | 잠정 자체 상위 분류 (기계·전기·화학·물리·작업 방법·환경). KRAS 공식 분류를 확인하면 교체 | 잠정임을 명시 |
| 통제 실패 | SIF 재해유발요인 참조 + 자유 기술 | 124종은 너무 세밀 → 상위 묶음 필요 (후속) |
| 예상 사고 형태 | 국내 발생형태 명칭 (떨어짐 … 빠짐·익사) | 사고 전 신고에서는 "예상", 사고 후에는 "실제" |
| 실제 피해 여부 | 없음 / 아차사고 / 부상 / 사망 / 불명 | 원문에 없으면 반드시 "불명" |
| 장소·시점 | 입력값 | 입력에 없으면 "불명" |

### 4.2 분류 하나에 기록할 항목

```json
{
  "axis": "예상 사고 형태",
  "scheme": "산업재해 발생형태 (고용노동부 「2024년 산업재해 현황분석」 재해유형 용어)",
  "scheme_version": "2025-12 발행본",
  "code": null,
  "code_status": "공식 숫자 코드 미확인",
  "label": "떨어짐",
  "assertion": "ai_inference",
  "evidence": "2층 계단 난간 일부가 빠져 있습니다",
  "needs_confirmation": true,
  "note": "원문은 난간 상태만 말함. 떨어짐은 예상 사고 형태로서의 추론"
}
```

### 4.3 관찰·추측·추론·제안 구분 (원문에 없는 정보를 확정하지 않기)

| `assertion` 값 | 뜻 | 조건 |
|---|---|---|
| `observed` | 신고자가 본 사실 | `evidence` 가 **원문에 그대로 있어야** 함 (자동 검사) |
| `reporter_speculation` | 신고자의 추측 | 원문 근거에 불확실 표현(것 같, 인지, 모르겠, 듯 등)이 있음. 정리 과정에서 단정으로 바꾸면 안 됨 |
| `ai_inference` | AI 의 추론 | 원문에 직접 없는 판단. **`needs_confirmation` 은 항상 true**. 신고서의 "확정" 칸에 들어가지 않음 |
| (별도 목록) `suggested_actions` | 개선조치 제안 | 분류와 섞지 않고 "검토용 후보"로만 표시 |

**검사 규칙** (기존 실험에서 사실 변경 18건이 나온 데 대한 대응)

- `observed` 의 근거가 원문에 없으면 오류로 처리합니다.
- 원문에 불확실 표현이 있는데 대응 항목이 `observed` 로 나오면 경고합니다.
- `실제 피해 여부` 는 원문에 명시가 없으면 "불명"만 허용합니다.
- 정리문(cleaned_description)은 선택 기능으로 두고, 기본값은 **원문 유지**로 둡니다.

## 6. SIF 제조업 사례로 평가하는 방법 (기존 코드에 맞는 사례만 고르지 않기)

두 가지를 **따로** 잽니다.

**(1) 분류체계 포괄률** — 모델 없이 계산합니다.

- 모집단: 제조업 1,546건 전체
- 축마다 SIF 라벨(고위험작업·상황, 재해유발요인, 기인물)이 새 체계의 값으로 표현되는지 라벨 단위로 판정하고, 사례 수로 가중합니다.
- 결과는 "직접 / 부분 / 체계 밖" 비율로 냅니다.
- 기존 24코드 체계의 포괄률(직접 14.5%)과 같은 방식으로 비교합니다.

**(2) 분류 정확도** — 모델 실행. 별도 승인 후에 합니다.

- **표본**: 전체 모집단에서 고위험작업·상황 기준 층화 무작위 추출(예: 100건, 시드 고정)
  - 포괄되는 사례만 고르지 않습니다.
  - 체계 밖 사례도 비율대로 포함합니다.
- **입력**: 재해개요만 넣습니다(업종·기인물·라벨·감소대책 제외. [sif_data_review.md 7장](sif_data_review.md)).
- **채점**
  - 포괄 사례: 축별 일치율을 냅니다(작업 활동, 설비·기인물, 통제 실패, 사고 형태).
  - 체계 밖 사례: 모델이 억지로 코드를 고르지 않고 "해당 없음/확인 필요"로 남겼는지(**적절 보류율**)를 냅니다.
  - `observed` 근거의 원문 존재율과 `ai_inference` 비율을 함께 냅니다.
- **사전 고정**: 원본 해시, 대응표, 표본 연번, 채점 규칙, 목표치를 실행 전에 커밋합니다.
- **해석 한계**: SIF 는 사고 후 서술문입니다. 이 결과는 사고 전 작업자 신고에서의 성능을 대신하지 않습니다.
